## Прораб — обещания проекта не теряются

В проекте установлен Прораб: один реестр просьб владельца `.foreman/promises.jsonl`. В каждом пункте — дословная цитата владельца и машинные пробы. Что сделано, вычисляет `.foreman/foreman.py` по пробам, а не по чьим-то словам. Хуки делают это автоматически:
- каждая просьба владельца попадает во «входящие» `.foreman/inbox.jsonl`;
- в конце хода приходит одно напоминание её разобрать;
- при старте сессии и после сжатия контекста приходит сводка из реестра.

Правила для Claude:
1. **Новая просьба по работе** → `python .foreman/foreman.py add '{"title": "…", "quote": "дословно", "priority": "high|normal|later", "next": "…", "probes": ["file:…", "grep:файл:регулярка"]}'`, затем `take I-… --as P-…`. Не задача → `skip I-… --why "…"`.
2. **Пробы** — 1–3 на пункт: такие, что позеленеют, ТОЛЬКО когда обещание выполнено. Виды:
   - `file:путь` (можно маску);
   - `grep:файл:регулярка` / `nogrep:файл:регулярка`;
   - `doc:файл:слово`;
   - `get:http://…`;
   - `cmd:…` — только если владелец включил `allow_cmd` в `.foreman/config.json`.
3. **«Сделано» руками не пишется** — его вычисляют пробы. Статусы вручную: `todo · doing · waiting · parked · accepted` (после приёмки владельцем) `· dropped` (только по его слову).
4. **Парковка.** Новая просьба посреди работы → сначала текущему пункту `set P-… status=parked next="следующий шаг"`, потом новое.
5. **«Что у нас по проекту?» / «сверка»** → `python .foreman/foreman.py status` и агент `foreman`: он судит, что сделано по смыслу, что забыто, три следующих шага. Отчёт — одним экраном, простыми словами.
6. **Сводка в начале сессии и после сжатия** — источник правды о незаконченном. Начинать с неё, а не с пересказа.
7. **Консилиум для сложного.** Пункт `high` дважды не прошёл пробы, решение дорого ошибиться (архитектура, данные, публичный API) или владелец просит «консилиум» / «подумай как следует» → навык `foreman-council`: сначала заморозить пробы и рубрику, затем 2–3 разных кандидата в git worktree, `foreman.py compare`, слепой судья `foreman-judge`, журнал `foreman.py round`. Оставлять ЛУЧШЕГО проверенного, а не последнего. Для простых задач консилиум не нужен.
